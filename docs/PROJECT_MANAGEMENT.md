# プロジェクトマネジメント計画（react-modern-site）

このドキュメントは、`react-modern-site` を安定運用しながら改善を進めるための実行計画です。

## 1. 目的（PM観点）

- ランディングページとしての成果最大化（CVR向上、離脱率低下）
- 開発速度を維持しつつ、品質事故を防ぐ（リリース手戻り削減）
- 広告/アフィリエイト運用を継続的に最適化（収益改善）

## 2. 成果指標（KPI）

- **開発KPI**
  - main ブランチのビルド成功率: 100%
  - 重大バグ（S1/S2）未解決期間: 7日以内
  - PR リードタイム（作成〜マージ）中央値: 2営業日以内
- **プロダクトKPI**
  - ページ表示速度（LCP）: 2.5秒以内
  - CVR: 前月比 +5% を目標
  - 広告CTR: 前月比 +3% を目標

## 3. マイルストーン（四半期）

### M1: 品質基盤の安定化（1〜2週）
- `npm run build` を必須チェックとして運用
- 主要ページ（Home / Products / Donate）の回遊導線レビュー
- ドキュメント整備（運用手順・リリース手順）

### M2: 計測と改善サイクル導入（3〜6週）
- KPIの週次トラッキング開始（CVR, CTR, LCP）
- ABテスト候補（CTA文言、バナー配置）を2件以上実施
- 成果レビュー会の定例化

### M3: 収益最適化と継続運用（7〜12週）
- 広告配置の最適化（ユーザー体験を損なわない範囲）
- アフィリエイトリンクの成果比較と差し替え運用
- リリース頻度を「隔週以上」に安定化

## 4. 役割と責任（RACI簡易版）

- **PM（あなた / 本計画のオーナー）**
  - 優先順位の決定、進行管理、KPIレビュー
- **開発担当**
  - 実装、レビュー対応、技術的負債の解消
- **デザイン/コンテンツ担当（兼務可）**
  - コピー改善、バナー素材更新、UI改善提案
- **運用担当（兼務可）**
  - 広告/アフィリエイト設定、成果集計、規約順守確認

## 5. バックログ優先順位（初期）

1. README の運用情報整備（導入者の立ち上がり時間短縮）
2. CTA導線の強化（`Home.jsx` / `Products.jsx`）
3. 広告表示条件の見直し（UXを崩さない配置）
4. パフォーマンス改善（画像最適化・不要レンダリング削減）
5. PDF出力スクリプトの運用手順化（必要時のみ）

## 6. 進行ルール（提案）

- **週次定例（30分）**
  - 先週実績（完了/未完了）
  - KPI差分の確認
  - 今週の優先タスク3つを確定
- **日次非同期更新**
  - 「昨日やったこと / 今日やること / ブロッカー」
- **リリース判断基準**
  - build 成功
  - 重大バグなし
  - 変更点が README またはPR本文に記録済み

## 7. リスクと対策

- **リスク**: 広告最適化を優先しすぎてUX悪化
  - **対策**: CTRだけでなく滞在時間・離脱率を同時監視
- **リスク**: 少人数で運用が属人化
  - **対策**: 手順を README / docs に明文化
- **リスク**: 計測不足で施策評価が曖昧
  - **対策**: KPI収集タイミングを週次で固定

## 8. 直近2週間アクション

- [ ] build/check 手順をチーム内で統一
- [ ] 改善候補チケットを5件作成（優先順位付き）
- [ ] CTA改善を1件リリース
- [ ] KPI週次フォーマットを作成し運用開始
